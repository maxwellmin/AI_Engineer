# Memories 示例模板

## 说明

Memories 用于存储跨会话的重要信息，如项目决策、进度记录、关键偏好等。Codebuddy 会根据需要检索这些信息。

## 文件命名规范

- 使用小写字母和下划线：`decisions.md`
- 常见分类：
  - `decisions.md` - 重要技术决策记录
  - `progress.md` - 开发进度记录
  - `preferences.md` - 用户偏好设置
  - `lessons.md` - 经验教训

---

# 技术决策记录

## 格式说明

每个决策记录包含：
- **日期**: 决策时间
- **背景**: 为什么需要做这个决策
- **选项**: 考虑过的方案
- **决策**: 最终选择的方案
- **理由**: 选择该方案的原因
- **影响**: 对项目的影响

---

## 决策 002: 使用阿里云通义千问作为 LLM Provider

**日期**: 2024-01-16

**背景**
需要选择 LLM 服务提供商用于 RAG 生成和 Embedding。

**选项**
1. OpenAI (GPT-4 + text-embedding-ada-002)
2. 阿里云通义千问 (Qwen + text-embedding-v1)
3. 本地部署 (Llama + BGE)

**决策**
选择阿里云通义千问。

**理由**
- 国内访问稳定，无需代理
- API 成本较低
- 中文处理能力强
- LangChain 原生支持

**影响**
- Embedding 维度为 1536
- 需要配置阿里云 API Key
- 使用 LangChain 的 Qwen 集成

## 决策 003: 文档分块策略

**日期**: 2024-01-20

**背景**
需要确定文档分割策略以优化检索效果。

**选项**
1. 固定长度分块（如 512 tokens）
2. 语义分块（基于段落/句子）
3. 递归分块（先按段落，再按句子）
4. 混合分块（结合标题层级）

**决策**
采用递归分块 + 标题层级结合的策略。

**理由**
- 保持语义完整性
- 尊重文档结构
- 避免关键信息被截断
- 便于上下文溯源

**影响**
- 分块大小不固定，需要元数据记录
- 检索时需要考虑父子块关系
- 实现复杂度较高

## 决策 004: 采用 TDD 开发模式

**日期**: 2026-02-14

**背景**
需要确定开发模式，确保代码质量和可维护性。

**选项**
1. 传统开发模式（先写代码，后写测试）
2. TDD 模式（测试驱动开发）
3. 无测试模式

**决策**
采用 TDD 开发模式。

**理由**
- 测试先行确保需求被正确理解
- 重构时有测试保护，更安全
- 文档化代码行为
- 减少回归问题

**影响**
- 开发节奏：先写测试，再写代码
- 需要 pytest-django 配置支持
- CI/CD 需要运行测试
